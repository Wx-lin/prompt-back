# 后台采集登录与定时管理实施计划

用户授权：快速在现有后台增加扫码登录引导、每日任务配置与执行状态，并部署到既有腾讯云项目。

设计：采集执行器在私有浏览器profile目录输出按任务ID隔离的二维码与状态；管理员接口鉴权后读取图片，前端使用带X-Admin-Key的fetch blob展示，密钥不放URL。缺少登录进入awaiting_login，刷新信号由拥有浏览器的执行进程处理，成功后继续，平台网络限制/验证码/接口错误分别展示。

定时配置持久保存于PostgreSQL；独立worker每分钟检查到期配置，以任务唯一约束和采集advisory lock避免重复。旧每天10/22的固定timer切换为分钟dispatcher，默认配置沿用每天10/22、20条、AI审核自动发布。运行记录保存采集数量、发布/待审核数量与阶段/失败原因。手动采集仍进入草稿，定时自动审核不处理历史pending。

- [ ] 后端表结构/迁移、CRUD、历史筛选与统计、私有QR鉴权API（schedule_backend）
- [ ] 执行器QR生命周期、会话保存/恢复、调度claim幂等、阶段和审核计数（crawl_runtime_ui）
- [ ] 管理端配置页面、日期统计、任务详情、可复用扫码对话框（schedule_admin_ui）
- [ ] root整合测试、构建、数据库备份和Alembic升级
- [ ] root停止旧timer、部署新分钟dispatcher、seed原有10/22默认配置
- [ ] root验证公网后台配置保存/暂停/时间数量、未登录二维码可见且鉴权、运行记录和下一次时间

回滚：部署前保存数据库dump和旧镜像ID，失败时还原容器/timer；数据库采用添加表/字段，不删现有业务数据。未授权用户读取QR需401/404，绝不暴露Cookie、CDP或浏览器目录。时间明确为Asia/Shanghai，数量1–50。
