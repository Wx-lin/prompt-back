# 2026-10-15 后台投稿分类误判复盘

## 影响与根因

正常投稿在审核页被误报为旧分类，无法审核。这不是用户选错分类，也不是 `portrait` key 失效；已有未发布投稿无需重新提交。

后台分类 hook 原来同源请求 `GET /api/categories`。生产 Nginx 只将 `/api/admin/*` 转发至 FastAPI，其余请求进入 Next.js，因此该请求实际收到 HTML 404，而非分类 JSON。分类加载失败后 `categories=[]`，UI 将有效的 `portrait` 误判为旧分类。

问题同时涉及生产请求路径和错误状态建模：未确认请求经过真实网关后的响应，就把目录加载失败解释成投稿数据错误。单元测试和构建通过不能证明生产链路正确。

## 修复

- 新增需认证的 `GET /api/admin/categories`，复用公开接口的 `list_categories(db)`，后台 hook 改用该路径，符合现有生产路由规则。
- 分类目录未加载时，不再提示投稿使用旧分类，并阻止批准，避免将依赖故障误报为用户数据问题。
- 最初考虑新增 Nginx route，但发布前发现 `update-backend.sh:115` 会保留线上 live gateway 配置，因此放弃该方案；仅修改仓库网关文件不能保证线上生效。

修复提交：[1dd043ab77af7b8ca941fd650dbfb1dad137c7dd](https://github.com/Wx-lin/prompt-back/commit/1dd043ab77af7b8ca941fd650dbfb1dad137c7dd)。部署记录：[GitHub Actions 38712258462，success](https://github.com/Wx-lin/prompt-back/actions/runs/38712258462)。

## 后续分类变更的强制上线门禁

1. **验证真实请求链路。** 从真实浏览器检查同源请求，追踪浏览器 → gateway/BFF → API；记录实际路径、HTTP 状态、`Content-Type` 和 JSON shape。HTML 404、认证失败、目录加载中、空目录必须与旧分类明确区分。
2. **验证认证边界。** 后台分类接口未认证应返回 401；使用有效后台身份应返回 200 和预期 JSON，不能只检查服务直连结果。
3. **验证目录一致。** 同源后台目录与公开目录的 12 个分类及 key 保持一致；投稿数为 0 的分类也应保留，不能由已有投稿反推完整目录。
4. **验证真实审核 UI。** 刷新线上审核页，检查已有投稿的分类回填、显示名称、全部选项和错误提示；目录未加载时必须阻止批准，且不能误报旧分类。
5. **控制验收副作用。** 批准和发布流程只使用经授权的测试数据；不得为验收擅自批准或发布用户投稿。未执行的流程必须明确标记未验证。
6. **核对部署配置机制。** 修改 gateway、Nginx 或 BFF 前，检查发布脚本是否保留、覆盖或生成线上配置，并验证最终生效配置；仓库文件变更不等于线上变更。
7. **以线上证据收尾。** 测试、构建、CI、健康检查是必要证据，但不能替代真实浏览器经过生产网关的业务验证。缺失的检查、跳过项和未完成的依赖审计必须如实记录。
