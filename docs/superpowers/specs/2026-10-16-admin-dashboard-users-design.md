# 后台数据大盘与用户管理

## 目标与范围

后台新增“数据大盘”和“用户管理”两个菜单，默认首页进入大盘。沿用现有布局、管理员鉴权和请求封装；保留“首页推荐”等既有入口。首版只读，不新增封禁、删除、密码或权限修改。

可选范围：仅做两个总数卡片实现最快，但难以判断内容库存；本方案增加发布状态和分类分布，足够日常运营；趋势分析与账号处置后续独立扩展，不把登录时间当成访问活跃度。

## 数据大盘

- 用户总量、启用/停用数量、北京时间今日新增用户；测试账号不自动排除或伪装成真实用户。
- 作品总量以 Prompt 表为准；已公开数量使用现有 public_prompt_condition；待审核、已拒绝、未公开其他作品分别展示，避免相互重复。采集草稿另列，不混入作品总量。
- 效果图总量单独统计，不当作作品数。
- 12 类分布展示中文名称、作品总量和公开数量；零库存分类保留；历史或未知分类单列“其他/历史分类”，确保能与总数核对。
- 卡片配合分类横条或表格，展示刷新时间与刷新按钮；失败显示错误与重试，不能用零冒充接口失败。

## 用户管理

- 服务端分页，默认注册时间倒序，以 ID 稳定排序。
- 支持昵称/邮箱关键词搜索、全部/启用/停用状态筛选；列表总数随筛选变化，另展示全站用户数。
- 字段：用户 ID、昵称、邮箱、账号状态、注册时间、最近登录时间；时间按北京时间显示，空值显示“未填写/暂无”。
- 不返回第三方身份标识、凭据或令牌；仅管理员可见。

## 接口与实现边界

全部新增接口位于已有 /api/admin/* 网关通道，如 GET /api/admin/dashboard 与 GET /api/admin/users。目录复用 app/utils/category_catalog.py，公开数量复用现有公开边界。SQL 聚合和筛选在服务层完成，分页不把全表拉到浏览器。不改数据库结构，不建立新外部依赖。

## 验收

先写聚合口径、搜索分页和鉴权测试，再实现。检查零库存/空库、待审与拒绝不算公开、未知分类、页边界、空用户字段及错误态。运行后端测试、后台类型检查/测试/构建。验证真实浏览器→现有网关→API 返回 JSON，并检查未鉴权 401、有效身份 200；线上没有实际验收不得宣称已上线。上线前按现有规则获得明确部署授权。
