# 分类优化本地实施计划

依据已确认的 `docs/aigc-prompt-分类优化需求.md`。用户已要求开始并继续；本地实现、测试和预演在授权范围内。生产数据修改和正式发布仍须清单审阅与明确授权，不在本地实现过程中执行。

1. 后端统一目录定义12类的key、中英文、排序和收录边界。分类接口保持现有key/label/count字段，追加label_en/order。投稿、后台创建编辑、采集归类及审核均使用目录校验。公开可见条件统一为已发布且review_status为空或approved。
2. 为 photography/image_edit/workflow 建立持久化原ID兼容集合；列表和搜索使用当前公开条件、模型和关键词SQL过滤后再分页。旧五类保留key，非法key返回422，不静默返回全站。
3. 主站复用当前分类导航和Base UI选择器：固定推荐与四个快捷分类，全部分类展示12类和数量。零库存不可浏览但可投稿，组合筛选为空不等于零库存。翻译与兜底目录增加一致性检查，保留其他筛选条件。
4. 后台从分类API加载目录，内容编辑、草稿审核和过滤共用；允许零库存类别，阻止提交旧类别。保留已存旧值可见但要求明确选择合法类别，不能默认替换未迁移内容。
5. 迁移工具默认只读预演。仅处理confirmed=true且审核动作明确的行；比对迁移前类别、发布审核状态及内容版本，在事务锁内跳过并发修改。每项写入持久化变更日志；重复执行不覆盖人工更改。回滚比对迁移后版本，只恢复受迁移影响的字段。迁移过程中不改ID/正文/图片/互动数据。发布状态变更单独批准并处理投稿图片ACL，初版工具不支持未经审核的发布状态修改。
6. 输出真实快照下的预演与待处理清单；所有已有建议confirmed=false，因此预演应显示0可应用，保留106条候选，不偷换人工确认状态。
7. 测试先RED再GREEN：目录、公开条件、非法/旧key、组合分页、后台校验、迁移重复执行/并发跳过/回滚。执行后端和前端相关单测与接口集成，lint/typecheck/build及关键桌面/手机E2E。由独立审查者检查正确性与安全。

工作分工：后端目录与兼容查询、主站接入、后台接入分别独立推进；主代理负责迁移工具和最终集成。当前前端已有用户修改的PROGRESS.md、site-header.tsx、user-menu.module.css及prompt-card.module.css，必须保留。

上线前置：23条已发布未解决内容的处理方案获运营确认；目录/兼容表及迁移验收通过；生产备份完成。不得因分类候选就下架或重写现有内容。
