# 后台管理面板（admin-panel）

> 这是运营方（也就是你自己）用来管理内容和处理举报的内部工具，**不是产品主站前端**。
> 产品主站前端由其他人/其他 Agent 独立开发，这个面板和主站没有任何代码关联，各自独立部署。

---

## 一、为什么是这种形态（技术选型说明）

**没有用 React/Vue 任何前端框架，纯 HTML + 原生 JS（`index.html` + `app.js`），零构建、零依赖。**

理由：
- 这是内部运营工具，使用者只有你自己，没必要为了"统一技术栈"上一套完整的构建流程
- 不需要 `npm install`、不需要 `webpack`/`vite` 打包，双击 `index.html` 或扔进任意静态服务器就能跑
- 代码量不大（一个页面 + 一个脚本文件），原生 JS 完全够用，不会出现"没有框架就难维护"的问题
- 如果以后运营团队扩大、功能变复杂，再考虑升级成 Vue/React 工程不迟，现在没必要为假想的未来复杂度买单

## 二、本地启动

### 2.1 启动后端服务（如果还没启动）

```bash
cd ~/Desktop/aigc-prompt-backend
uv run uvicorn app.main:app --reload --port 8000
```

### 2.2 启动管理面板的静态服务器

```bash
cd ~/Desktop/aigc-prompt-backend/admin-panel
python3 -m http.server 5500
```

然后浏览器打开 `http://localhost:5500`。

> **⚠️ 必须注意 CORS 配置**：后端 `.env` 的 `CORS_ORIGINS` 必须包含管理面板实际跑的地址（默认是 `http://localhost:5500`），否则浏览器会拦截所有请求，报 `CORS policy` 错误。`.env.example` 里已经把这两个地址都加好了，如果你改了管理面板的端口，记得同步改 `.env` 里的 `CORS_ORIGINS`。

### 2.3 登录

打开页面后，输入 `.env` 里配置的 `ADMIN_SECRET_KEY`，再确认一下"后端地址"是否正确（默认 `http://localhost:8000`），点登录。

密钥只存在浏览器 `sessionStorage` 里，关闭标签页就失效，不会持久化到硬盘，也不会在不同浏览器标签间自动同步（但同一个标签打开的新标签页会复用，这是浏览器 sessionStorage 的标准行为）。

## 三、功能说明

### 3.1 内容管理

- 查看全部内容（可按"已发布/草稿"筛选）
- 新建内容：填写标题、提示词原文、分类、适用模型（逗号分隔）、作者名、来源链接、效果图URL（逗号分隔多张），可选择"创建后直接发布"或先存草稿
- 编辑内容：点"编辑"会预填当前所有字段。**注意：编辑时效果图URL输入框默认留空，如果不想改图片就不要填，一旦填了会整体替换原有图片列表**（这是后端 `PATCH` 接口的设计，不支持"只改第二张图"这种细粒度操作，见 `AGENT.md`）
- 发布 / 下架：一键切换，立即影响用户在产品主站是否能看到这条内容
- 删除：彻底删除，不可恢复，会有二次确认弹窗

### 3.2 举报管理

- 查看举报列表（可按"待处理/已处理"筛选），自动关联显示被举报内容的标题
- 处理举报：填写处理备注，可选"同时下架这条内容"（勾选后会联动把对应内容的发布状态改成下架，不需要再手动去内容管理页操作一次）

## 四、关于图片上传

当前版本**没有做"选择本地图片直接上传"的功能**，效果图字段需要你先把图片传到阿里云OSS（或任何图床），拿到图片URL后手动填进输入框。

原因：
1. 阿里云OSS密钥还没申请配置（见 `PROGRESS.md` 待办）
2. MVP阶段内容量不大（50-100条起步），手动准备好URL再填表，操作成本可接受
3. 等OSS配置好、内容量上来后，如果觉得手动准备URL太繁琐，可以再加一个"选择文件→自动上传OSS→自动填入URL"的功能，现在不是必须的
